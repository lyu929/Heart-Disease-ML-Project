# heartrisk — leakage-free heart-disease risk modelling

[![CI](https://github.com/lyu929/Heart-Disease-ML-Project/actions/workflows/ci.yml/badge.svg)](https://github.com/lyu929/Heart-Disease-ML-Project/actions/workflows/ci.yml)

Predicts the probability of angiographic coronary artery disease from 11 routine clinical variables
(918 patients from four hospitals). The repository started as a group course project; this version
rebuilds it as an installable package with a reproducible, statistically sound evaluation and a small
prediction service:

* **Nested, repeated cross-validation.** 5×5 outer folds, inner-CV tuning, and the decision threshold
  chosen on *training* out-of-fold predictions.
* **Leakage audit.** The original code tuned the threshold on the test fold. That inflated F1 by about
  0.01 (p < 0.02 for every model), and it still produces better-than-chance results when the labels are
  randomly shuffled.
* **Honest uncertainty.** Corrected resampled t-tests (Nadeau–Bengio) with Holm adjustment, and
  bootstrap confidence intervals.
* **Beyond accuracy.** Calibration (intercept, slope, reliability), decision-curve analysis,
  permutation importance, and exact Shapley explanations.
* **Leave-one-hospital-out validation.** The four source hospitals are recovered from `heart.csv`
  (checked against the published cohort composition).
* **Deployment.** A versioned model bundle with a model card, a FastAPI service, a Streamlit UI, Docker,
  and CI.

Full results: **[reports/REPORT.md](reports/REPORT.md)** (generated by `heartrisk study`).

## Key results

| Model (5×5 nested CV) | ROC-AUC (corrected 95% CI) | Brier | F1 @ OOF threshold |
|---|---|---|---|
| Logistic regression | 0.929 (0.908–0.950) | 0.102 | 0.885 |
| **Logistic regression, deployed recipe** (no missing indicator) | 0.923 (0.902–0.944) | 0.107 | 0.877 |
| Random forest | 0.930 (0.906–0.953) | 0.101 | 0.886 |
| XGBoost | 0.930 (0.909–0.951) | 0.098 | 0.888 |
| Hist. gradient boosting | 0.931 (0.911–0.952) | 0.097 | 0.885 |
| MLP | 0.922 (0.899–0.946) | 0.110 | 0.876 |
| Stacking (LR + RF + XGB) | 0.933 (0.912–0.955) | 0.096 | 0.891 |

* **No model beats logistic regression on AUC** after correction for overlapping folds and multiple
  comparisons (all Holm-adjusted p = 1.0). Stacking has a slightly lower Brier score, which is not worth
  its complexity. The transparent model is deployed.
* **Generalisation across hospitals is the real limit.** With each hospital held out, logistic
  regression's AUC ranges from 0.79 to 0.96 (Switzerland 0.79, Cleveland 0.84, VA 0.85, Hungary 0.96).
  The calibration intercept shifts by +2.2 on the Switzerland cohort, which has 93 % prevalence.
* **The data has a recording artefact.** Cholesterol is 0 for 172 patients (the whole Swiss cohort and
  a quarter of the VA cohort), and 88 % of them have the disease. The zeros are treated as missing inside
  the pipeline. A missing-value indicator raises the cross-validated AUC by 0.006 (not significant), but
  it does so by recognising high-prevalence hospitals. The deployed model therefore leaves it out, so an
  unmeasured cholesterol no longer pushes a patient's risk up. For the example patient, risk with
  cholesterol unmeasured vs measured is 0.955 vs 0.955 without the indicator, and 0.989 vs 0.943 with
  it.
* **Class-imbalance handling does not help here.** On Framingham (15 % events), SMOTE made both
  discrimination and calibration worse: AUC 0.687 vs 0.705 for plain random forest, and Brier 0.143 vs
  0.119.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[api,ui,dev]"          # add ,torch for the optional PyTorch model

heartrisk study                         # full study -> reports/REPORT.md (~10 min on 2 cores; --quick for a smoke run)
heartrisk train                         # fit the deployable bundle -> models/heartrisk.joblib (+ model card JSON)
heartrisk predict patients.csv -o predictions.csv
heartrisk explain patient.json          # exact Shapley values for one patient
heartrisk serve                         # REST API on http://127.0.0.1:8000 (docs at /docs)
streamlit run app/streamlit_app.py      # web UI
docker compose up --build               # API on :8000, UI on :8501
```

Every setting lives in [`src/heartrisk/configs/default.yaml`](src/heartrisk/configs/default.yaml) and can be
overridden: `heartrisk evaluate --models logreg,xgb --set evaluation.repeats=10 --set evaluation.threshold.strategy=youden`.

### REST API

```bash
curl -s localhost:8000/v1/predict -H 'content-type: application/json' -d '{
  "Age": 54, "Sex": "M", "ChestPainType": "ASY", "RestingBP": 140, "Cholesterol": null,
  "FastingBS": 0, "RestingECG": "Normal", "MaxHR": 122, "ExerciseAngina": "Y",
  "Oldpeak": 1.5, "ST_Slope": "Flat"}'
```

```json
{"model": "Logistic regression", "model_version": "logreg-2026-10-07",
 "results": [{"probability": 0.955, "prediction": 1, "threshold": 0.417, "risk_band": "high",
              "warnings": ["Cholesterol missing: imputed with the training median"]}]}
```

| Endpoint | Purpose |
|---|---|
| `GET /health` | liveness and whether a model is loaded |
| `GET /v1/model` | model card: threshold, CV performance, training-data hash, intended use |
| `POST /v1/predict` | one patient or a list (≤ 1000); validated ranges and enums; unmeasured values are `null` |
| `POST /v1/explain` | per-variable Shapley contributions that sum exactly to prediction − baseline |

Inputs are validated with pydantic. Out-of-range values return 422, and values outside the training range
come back as warnings.

## How the evaluation works

```
for each of 5 repeats × 5 outer folds (same splits for every model):
    inner 5-fold grid search on the outer-training part          (hyper-parameters)
    inner 5-fold out-of-fold predictions on the outer-training part
        -> decision threshold (F1 / Youden / target sensitivity)  (frozen)
    refit on the outer-training part, score the untouched test fold
```

* **All preprocessing is inside the pipeline.** This covers zero → missing, median imputation with
  missing indicators, scaling and one-hot encoding. CV folds, the saved bundle and the API therefore run
  identical code.
* **Model comparisons use per-fold paired differences.** These go through the corrected resampled t-test
  (variance × (1/J + n_test/n_train)) with Holm adjustment, and the corrected CIs are shown in the tables.
* **Leakage audit with no extra fitting.** Each fold also stores the metrics the legacy protocol would
  have reported (`leaky_*` columns), so the optimism is measured on the same fitted models.
* **Leave-one-hospital-out.** Each hospital in turn is the test set, with tuning and the threshold
  learned on the other three.

More detail: [docs/legacy_mapping.md](docs/legacy_mapping.md) (what changed relative to the course
code, and why), [docs/data.md](docs/data.md) (data provenance and caveats), and
[MODEL_CARD.md](MODEL_CARD.md).

## Testing

```bash
pytest -m "not slow"     # ~2 min: unit, API, CLI and UI tests
pytest                   # + end-to-end quick study
ruff check . && ruff format --check .
```

The most important test is `test_test_labels_never_influence_threshold_or_predictions`. It scrambles the
test-fold labels and asserts that the threshold and the predictions do not change, while the legacy
(test-tuned) threshold does.

## Intended use and limitations

This is a research and teaching demonstrator, **not a medical device**:

* The data is small, retrospective and decades old, and comes from referral populations with high
  prevalence (55 %).
* Hospital-level shift is large (Section 3.6 of the report).
* Probabilities are only meaningful for populations like the training data.

## Data

`data/heart.csv` is the public Kaggle "Heart Failure Prediction" dataset (fedesoriano, 2021). It merges
the UCI Heart Disease cohorts from Cleveland, Hungary, Switzerland and the VA Long Beach hospital.
`cleveland_processed.csv` and `framingham_processed.csv` are pre-standardised teaching extracts that are
used only for within-cohort benchmarking. See [docs/data.md](docs/data.md).
